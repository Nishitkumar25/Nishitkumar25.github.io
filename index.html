capstone_04 / full-stack development · e-commerce

PawPantry — Full Stack Pet Supplies E-commerce Platform

Overview

PawPantry is a full-stack e-commerce application built as a Perficient capstone. It joins two independently developed halves — a React storefront and a Spring Boot REST API — into one working store. Shoppers browse and search the catalogue, fill a cart, check out, track orders and subscribe to repeat deliveries; store managers run the catalogue and orders from an admin area. The server owns every decision that matters: prices, stock, roles and order state.

Full-stack integration

The browser only ever talks to the Vite dev server, which forwards /api/* to Spring Boot. That gives one origin, no CORS, and a strict same-site refresh cookie. The frontend consumes the API through RTK Query; the backend exposes it under an OpenAPI 3 contract with a matching Postman collection, so both halves are developed against the same documented interface. Shared test vectors keep cart pricing identical on both sides of the wire.

  • Stateless JWT sign-in: a 15-minute access token plus a hashed, rotating 7-day refresh cookie, BCrypt password hashing, account lockout and rate limits.
  • Server-side pricing only — per-category GST shown line by line and free shipping above a threshold — so the client can never set a price.
  • Idempotent order creation, ETags and optimistic locking on admin edits, a payment reconciliation job, an outbox and server-sent events for live order updates in every open tab.
  • PostgreSQL schema owned by Flyway migrations (V1–V17); the API is validated against the schema rather than generating it.

Technology stack

frontend
React 19 · Vite 8 · React Router 6 · Redux Toolkit 2 with RTK Query · JavaScript
backend
Java 21 · Spring Boot 3.5 · Spring MVC · Spring Data JPA · Spring Security · REST APIs · JWT authentication
database

testing
JUnit 5 · MockMvc · ArchUnit · JaCoCo · Vitest · Testing Library · Playwright with axe accessibility checks

Key features

  • User registration, sign-in and account management
  • Product catalogue with admin product management
  • Server-side search, category / brand / price / rating filters, sorting and paging
  • Product reviews and ratings with a verified-purchase badge
  • Shopping cart and wishlist, including guest carts merged on sign-in
  • Three-step checkout with an idempotency key
  • Order management and tracking with a status timeline, cancel window and PDF invoice
  • Subscribe & Save: pause, resume, skip, change or cancel a repeat delivery
  • Admin orders, sales report, audit log and CSV import
  • Natural-language catalogue search whose filters are validated server-side

Honest status

Payment processing is implemented as Cash on Delivery plus a mock card gateway, with every outcome handled explicitly (approved, declined, timeout, gateway failure, answer lost). No live third-party payment provider is integrated. All modules are built and tested, but milestones are marked "built" rather than signed off: several manual browser checklists are outstanding, the database-dependent tests have so far run against mocks, and browser testing has been Chromium-only.

capstone_06 / enterprise application · fintech

Wealth Management — New Account Opening Platform

Overview

An enterprise-oriented financial services application for digital account onboarding in wealth management. A client registers, completes an application made up of fifteen information sections, uploads identity and KYC documents, answers a risk-profiling questionnaire, signs the regulatory declarations and submits. Operations and Compliance staff then review the submission, verify the documents, record remarks and approve, return or reject it. Administrators manage staff accounts and read the audit trail and aggregate reports.

Architecture

A modular monolith: one Spring Boot application and one PostgreSQL database, with packages organised by business feature and the same controller → service → repository → entity layering inside each. The API is REST/JSON under /api/v1, stateless, documented with OpenAPI, and every error passes through one global handler into a standard response envelope. The database schema is owned by Flyway (V1 through V22) and the application validates against it rather than generating it. Uploaded documents go to a local file system behind a storage interface, and sensitive fields such as bank account numbers are encrypted at the field level.

Business functionality implemented

  • Customer registration, login and profile
  • Personal information and residential address capture
  • Identification details and employment information
  • Financial information and banking details
  • Investment profile and risk-profiling questionnaire
  • FATCA / CRS tax declaration and PEP screening
  • Regulatory consents and e-signature
  • Beneficiary management and trusted contact
  • Document upload by category, with OCR extraction used to cross-check the details on the document
  • KYC verification by Operations
  • Application submission, with edits locked afterwards
  • Application status tracking and immutable status history
  • Operations and compliance review with reviewer remarks and approve / return / reject decisions
  • Append-only audit log, aggregate reports and admin staff-account management

capstone_07 / fintech · dashboard · data visualization

Advisor360 — Wealth Management Portfolio & Household Dashboard

Overview

Advisor360 is the second half of the same wealth-management product: once a customer's account application is approved, an advisor serves them. It gives the advisor a consolidated view of their book — clients, households, portfolios, assets under management and risk indicators — on one dashboard, and continues from monitoring into concrete, explained suggestions.

Architecture

A separate Python service alongside the onboarding backend. It owns its own PostgreSQL schema, migrated with Alembic, and reads the onboarding side through exactly two read-only database views — so client onboarding data is never duplicated or written from here. Both services accept the same access token, so one sign-in covers the whole product, and the React website routes advisor paths to this service and everything else to the onboarding API. Twenty-six endpoints, a shared response envelope, request ids on every response, and paging on every list.

Business functionality implemented

  • Advisor homepage with summary tiles, charts and clients needing attention
  • Client 360-degree overview: profile, risk profile, AUM, accounts, alerts and recommendations
  • Paged client list with search and filters by risk profile, household and alert state
  • Household management with members and combined AUM
  • Portfolio overview per client and across the whole book
  • Asset allocation, sector and account-type analysis with top holdings
  • Assets Under Management reporting
  • Investment risk monitoring with a database-driven rule engine
  • Alert lifecycle: open → acknowledged → resolved, with a real breach reappearing at the next check
  • Portfolio insights and financial recommendations an advisor can accept or dismiss
  • Onboarding hand-off: approved applications pulled into advisors' books, with an assignment suggestion and the data behind it
  • Firm-level reports, append-only audit trail, and client reassignment for administrators

Portfolio risk indicators

  • High equity — equity allocation above 80% of the portfolio.
  • Idle cash — cash allocation above 25% of the portfolio.
  • Concentration — a single stock above 30% of the portfolio.

Each threshold is stored in the database so it can change without a code change, and comparisons use exact decimal arithmetic rather than floating point: 80.00% is not a breach, 80.01% is. A breach raises an alert, and each alert type maps to one recommendation type — reduce equity, deploy cash or diversify — carrying the measured percentage, the limit, the target and a written rationale.

These are risk-monitoring indicators for a qualified advisor to act on, not investment advice. Accepting a recommendation records the advisor's decision; nothing is traded. The targets and margins behind the suggested amounts are placeholders awaiting business sign-off, and no AI model is called — the optional narration is a local template.

Research

Adaptive Emotion-Aware Speech Therapy Framework for Dysarthria Using AI

problem
Conventional dysarthria therapy applies fixed exercise routines, ignoring each speaker's unique impairment profile severity, accent, and emotional state during a session.
motivation
Therapy is more effective when it adapts. A framework that continuously reads the speaker's speech and emotion signals can keep exercises challenging but achievable, and adjust when the speaker is struggling.
methodology
Speech input is preprocessed and reduced to acoustic features. Models classify speech characteristics, emotion, and severity; the assessment feeds an adaptive therapy generator that selects and stages exercises; feedback updates the next round.
ai / ml approach
Machine and deep learning classifiers over extracted speech features for emotion and severity estimation, with accent-aware feature handling, and a rule-informed therapy decision layer that converts model output into staged exercise plans.
dataset context
Developed as a research framework, evaluation targets standard dysarthric and emotion speech corpora in the domain.
contribution
Defined the adaptive therapy decision layer that connects speech/emotion analysis to severity-appropriate exercise generation turning a one-size-fits-all therapy model into a measurable, feedback-driven system.
